2026-09-09 11:15 - REFACTOR: Replaced native <select> with custom dropdown components
  Files modified:
  - static/index.html:
    * Les 4 <select> (Display Mode, Interval, Transition, Order) remplacés
      par des <div class="custom-select"> avec trigger + <ul> d'options
  - static/css/styles.css:
    * Supprimé `.setting-row select`
    * Ajouté tout le système `.custom-select` :
      - .custom-select-trigger : bouton avec flèche ▼ animée
      - .custom-select-options : dropdown avec opacity/transform transition
      - .custom-select.open : ouvre avec animation
      - li:hover / li.selected : états visuels
  - static/js/settings.js:
    * Nouvelles fonctions : selectOption(), readSelectValue(),
      setupCustomSelects()
    * setupCustomSelects() gère :
      - Click trigger → toggle open/close (ferme les autres)
      - Click li → sélectionne + ferme + sauvegarde dans localStorage
      - Click outside → ferme tout dropdown ouvert
    * applyToUI / readFromUI réécrits pour lire/écrire via data-value
      au lieu de .value de <select>
  Raison : Les <select> natifs dans WKWebView utilisent des NSPopUpButton
  (AppKit natif). Les moniteurs clavier Swift (NSEvent.addLocalMonitor)
  interceptent les touches avant la popup native, rendant les <select>
  inutilisables. La solution custom composée uniquement de <div>/<ul>/<li>
  évite complètement le problème — aucun composant AppKit n'est impliqué,
  tout est géré en HTML/CSS/JS pur.
